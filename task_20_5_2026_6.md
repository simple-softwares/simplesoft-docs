```python
class StockMovementIn(BaseModel):
    product_id: int
    movement_type: Literal['in', 'out', 'adjustment']
    quantity: float           # for 'adjustment', this is the NEW absolute stock level
    reference: Optional[str] = None
    notes: Optional[str] = None

class StockMovementOut(BaseModel):
    id: int
    product_id: int
    product_name: str         # joined from Product
    movement_type: str
    quantity: float
    reference: Optional[str]
    notes: Optional[str]
    moved_by_name: str        # joined from User
    created_at: datetime

class ProductStockOut(BaseModel):
    id: int
    name: str
    sku: Optional[str]
    barcode: Optional[str]
    category: Optional[str]
    unit: Optional[str]
    product_type: str
    selling_price: float
    cost_price: Optional[float]
    gst_rate: float
    current_stock: float
    reorder_level: float
    is_low_stock: bool        # current_stock <= reorder_level
    is_active: bool

class InventoryValuation(BaseModel):
    total_products: int
    total_stock_value: float  # SUM(current_stock * cost_price) where cost_price is not null
    low_stock_count: int
    out_of_stock_count: int
    by_category: list[dict]   # [{category, count, stock_value}]
```

### Endpoints

```
POST /inventory/movement
    Body: StockMovementIn
    Logic:
      - Fetch product (404 if not found in workspace)
      - If movement_type == 'in':  product.current_stock += quantity
      - If movement_type == 'out':
          if product.current_stock < quantity: raise HTTPException(400, "Insufficient stock")
          product.current_stock -= quantity
      - If movement_type == 'adjustment':
          delta = quantity - product.current_stock
          product.current_stock = quantity
          # store delta as the actual quantity moved (for history readability)
      - Insert StockMovement row
      - Commit, return StockMovementOut

GET /inventory/movements
    Query params: product_id (optional int), limit (default 50, max 200)
    Returns list[StockMovementOut], ordered by created_at DESC
    Join: products.name, users.name

GET /inventory/low-stock
    Returns list[ProductStockOut] where current_stock <= reorder_level AND is_active == True
    Ordered by (current_stock / reorder_level) ASC nulls last (most critical first)

GET /inventory/valuation
    Returns InventoryValuation
    Queries:
      - total_products: COUNT(*) active products
      - total_stock_value: SUM(current_stock * cost_price) where cost_price IS NOT NULL
      - low_stock_count: COUNT(*) where current_stock <= reorder_level
      - out_of_stock_count: COUNT(*) where current_stock <= 0
      - by_category: GROUP BY category, SUM(current_stock * cost_price), COUNT(*)

GET /inventory/products
    Same as GET /products but includes current_stock and reorder_level fields.
    Returns list[ProductStockOut].
    Query params: search, category, low_stock_only (bool), active_only (default True), limit
```

## Part 3 — Auto-Reduce Stock on Invoice Send

In `routers/invoices.py`, inside `POST /invoices/{id}/send`:

After changing `invoice.status = "sent"` and creating journal entries, add:

```python
# Auto-reduce stock for product lines
for line in invoice.lines:
    if line.product_id:
        prod_result = await db.execute(
            select(Product).where(Product.id == line.product_id).with_for_update()
        )
        product = prod_result.scalar_one_or_none()
        if product and product.current_stock >= float(line.qty):
            product.current_stock -= float(line.qty)
            db.add(StockMovement(
                workspace_id=current_user.workspace_id,
                product_id=line.product_id,
                movement_type='out',
                quantity=float(line.qty),
                reference=invoice.invoice_number,
                notes=f"Auto: Invoice {invoice.invoice_number}",
                moved_by=current_user.id,
            ))
```

Import `Product` and `StockMovement` at top of invoices.py.
Stock reduction is best-effort — if stock is 0 or product not found, skip silently (don't block invoice send).

## Part 4 — Frontend: Rebuild `InventoryPage.jsx`

### Layout

```
┌──────────────────────────────────────────────────────┐
│ [Stock Value ₹X] [Products N] [Low Stock N] [OOS N]  │  ← stats from GET /inventory/valuation
├──────────────────────────────────────────────────────┤

│ ...                                                   │
│ [Stock In] [Stock Out] [Adjust] (per row action btns)│
└──────────────────────────────────────────────────────┘
```

**Stock count cell coloring:**
- `current_stock <= 0` → red text "Out of Stock"
- `current_stock <= reorder_level` → amber text + warning icon
- Otherwise → green text (or just normal)

### Sub-components

**`StockModal({ product, mode, onDone, onClose })`**
- `mode` = 'in' | 'out' | 'adjustment'
- Shows: product name, current stock, qty input, reference input, notes input
- For 'adjustment': label the input "New Stock Level" (not "Quantity")
- Submit calls `POST /inventory/movement`
- On success: refresh product list

**`ProductForm({ product, onDone, onClose })`**
- Add/edit product (uses `POST /products` or `PATCH /products/:id`)
- Fields: name*, SKU, category, HSN/SAC, unit, product_type (goods/service), selling_price*, cost_price, gst_rate*, barcode, reorder_level
- Slide-in panel from the right (or modal)

**`MovementsDrawer({ product, onClose })`**
- Slide-in panel: full movement history for one product
- Calls `GET /inventory/movements?product_id=N`
- Shows: date, type badge (In/Out/Adjust), qty, reference, moved by

### Two-tab layout

```
[Products] [Movements]
```
- **Products tab**: Table with stats row above
- **Movements tab**: Full workspace-wide movement log (GET /inventory/movements, no product filter), with product name column
